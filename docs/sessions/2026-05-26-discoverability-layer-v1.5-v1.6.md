# Session: v1.5.0 + v1.6.0 — structured discoverability layer + skill auto-activation hardening

**Date:** 2026-05-26
**Branch:** main
**Participants:** Filip, Claude Opus 4.7 (1M context)
**Duration:** ~one extended session

## Context

Repo was at v1.4.5 (deterministic security hooks + 10 skills + ADR/session
conventions from v1.3.0). Filip raised two questions over the session:

1. Article-fed checklist of what an "AI-first" sustainable repo should
   contain. Three items mapped to real gaps in the stack: a domain
   glossary, machine-readable architecture metadata, and (separate
   issue) "what's missing here?" as a first-class audit. The other
   article items were either already covered or out of scope as
   project-level concerns.
2. Empirical observation that skills were "minimally invoked" during
   normal dev. Research confirmed this is a known 2026 Claude Code
   runtime issue: multi-line `description: |` block scalars can have
   the auto-activation trigger silently dropped (parser-takes-first-line
   failure mode; ~40% of reported "slash works, autofire doesn't"
   cases).

Two coherent releases came out of the same arc.

## What was done

- **v1.5.0** (commit `31c8fe3`) — `/glossary-init` + `/arch-map` skills,
  `GLOSSARY.md` + `architecture.yml` conventions at repo root,
  templates for both, ADR 0005, skill count 10 → 12.
- **v1.6.0** (commit `a4f5788`) — `/repo-doctor` AI-readiness audit
  (~15 dimensions, `--score` / `--json` / `--fail-on` for CI),
  mechanical `description: | → >` across all 13 SKILL.md files
  (folded scalar fix for the auto-activation parse bug),
  `skill-cheatsheet.sh` SessionStart hook (gated on
  `claude-leverage:` marker in AGENTS.md, rate-limited 14-day per
  repo), ADR 0006, hook count 6 → 7, skill count 12 → 13.
- Two rounds of subagent code review (Sonnet, read-only). Round 1:
  v1.6.0 only, came back "Ship it" with two Important findings on
  band-gap intervals — applied before commit. Round 2: cross-version
  pass on v1.5.0 + v1.6.0 pre-push, one Important on an ADR 0006
  math typo — fixed in a third commit on top of the two release
  commits.

## Key decisions

- **Per-folder YAML metadata files (the alternative pattern Filip
  surfaced) was rejected.** AGENTS.md per folder is the convergent
  2026 standard (OpenAI ships 88 files in its main repo; 60K+ public
  repos; human-curated AGENTS.md beats LLM-generated by ~4pp on task
  success). YAML-per-folder would compete with that standard;
  `architecture.yml` at repo root is the *complementary* structured
  layer, not a replacement. Documented in [ADR 0005](../adr/0005-structured-discoverability-glossary-and-architecture-yml.md).
- **`/repo-doctor` stays separate from `/init-repo` and
  `/stack-check`.** Three distinct audiences: `/init-repo` = "set
  this fresh repo up" (writes files); `/stack-check` = "what I have,
  is it stale?" (freshness); `/repo-doctor` = "what I don't have,
  what's missing?" (completeness). Merging would muddy each.
  Documented in [ADR 0006](../adr/0006-repo-doctor-skill-discoverability-and-folded-scalar.md).
- **Per-module skills explicitly out of scope** even though
  `paths:` glob restriction is technically supported. Maintenance
  cost > marginal value over AGENTS.md-per-folder + architecture.yml
  + GLOSSARY.md trio. Revisit only if a concrete use case appears.
- **Test coverage % checking not added to `/repo-doctor`.** The
  test/source LOC ratio (Dimension 11) is a cheap read-only proxy;
  actual coverage requires running tests (per-language tooling, slow).
  Filip surfaced this mid-session; decided to skip rather than
  half-do.
- **Skill auto-activation fix mechanical, not behavioral.** Folded
  scalar (`>`) yields single-string runtime value with no internal
  newlines, sidesteps the documented parse bug without changing the
  description content semantically.

## Open questions

- Whether the v1.6.0 cheatsheet hook actually lifts auto-activation
  recall in practice — empirically unverifiable without running
  controlled sessions. We're trusting the published field reports and
  the gating story limits the downside.
- Whether `/repo-doctor`'s Dim 8 (anchor density) gap for
  sub-1000-LOC repos warrants an explicit "N/A under 1000 LOC" rule.
  Flagged as Nice in cross-version review; left as-is for v1.6.0,
  candidate for v1.6.1 or v1.7.
- Whether `plugin.json`'s `description` should track marketplace.json
  on each release. They drifted at v1.6.0; only marketplace.json
  surfaces in `/plugin install`, so user-visible is unaffected, but
  the drift will widen silently each release. Candidate for
  `scripts/check_version_sync.py` extension.
- Coverage-config presence as Dim 16 deferred (v1.6.1 candidate per
  decision above).
